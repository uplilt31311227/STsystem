# V2 教師名單 CSV 批次匯入（Phase 4b）

> 對應程式：`src/js/modules/v2/teacherAccountManager.js` 的 `importRosterCsv()`，
> UI 入口：「教師管理」頁籤 →「📥 批次匯入 CSV」按鈕（僅教務主任可見/可操作）。

## 用途

全校 30+ 位教師 onboarding 時，不需在「教師管理」頁一位一位用新增教師手動輸入，
改由教務處準備一份 CSV 名單，一次匯入。也可用於學期初補登新進教師、或幫既有教師
補齊 email / 角色 / 領域 / 導師班資料。

## CSV 欄位規格

檔案需為 UTF-8 編碼、第一列為表頭，欄位名稱須完全一致（順序不拘）：

| 欄位名稱 | 是否必填 | 說明 |
|---|---|---|
| `姓名` | **必填** | 教師姓名，用來比對是否為既有教師（新增或更新的依據）。留空該列會被記為錯誤並跳過。 |
| `Email` | 選填 | 教師登入帳號。留空表示暫不指派（該教師尚無法登入，之後可在教師管理頁補填）。 |
| `角色` | 選填 | 見下方「角色對照表」。留空時：新增教師預設為 `teacher`；更新既有教師則保留原角色不變。 |
| `領域` | 選填 | 任教領域，可填多個，用 `、`、`;`、`,`、`，` 其中一種分隔（見下方範例）。 |
| `導師班` | 選填 | 例如 `701`。純文字欄位，不做格式驗證。 |

## 角色對照表

角色欄位同時接受中文與英文代碼（大小寫皆可）：

| 中文（全稱） | 中文（簡稱） | 英文代碼 | 對應角色 |
|---|---|---|---|
| 教務主任 | 主任 | `director` | 主任：最高權限，含教師管理、學校設定 |
| 教學組長 | 組長 | `section_chief` | 組長：可核准/駁回申請、上傳課表、月結算 |
| 教師 | 老師 | `teacher` | 一般教師：申請代調課、回應同意邀請 |

其他任何值（例如打錯字、簡體「组长」、職稱以外的文字）都視為**不合法**，該列記為錯誤並跳過，
不會用預設值頂替，避免誤植角色。

## 衝突處理規則（冪等性為硬需求）

匯入採「兩段式」：先 `dryRun` 計算預覽，使用者確認後才真正寫入。**同一份 CSV 重複匯入兩次，
Firestore 最終狀態必須相同**，規則如下：

1. **姓名已存在於教師名單** → 更新該筆資料，計入「更新」。
   - CSV 留空的欄位（Email / 角色 / 領域 / 導師班）一律**保留原值，不會清空或打回預設**。
     例如某教師已被主任在教師管理頁手動設為「組長」，之後重新匯入一份角色欄位留空的 CSV，
     不會把她打回「教師」。
   - 若逐欄比對後與現況完全相同（沒有任何欄位真的變動），該列改計入「略過」而非「更新」——
     這也是同一份 CSV 重複匯入時，第二次通常會呈現「全部略過、新增 0、更新 0」的原因。
2. **Email 已被其他教師使用** → 該列記為錯誤並跳過，不會搶走別人的登入帳號。
3. **同一份 CSV 內有多列填了相同 Email** → 第一列（由上往下）勝出，其餘列記為錯誤並跳過。
4. **姓名空白** → 記為錯誤並跳過（此欄必填）。
5. **角色值不合法** → 記為錯誤並跳過（見角色對照表）。

匯入預覽與正式匯入的回傳結構相同：

```
{
  created: [...],   // 本次新增的教師
  updated: [...],   // 本次更新的教師
  skipped: [...],   // 資料與現況相同、無需異動
  errors:  [{ row, name, reason }, ...]   // row 為 CSV 中的列號（表頭算第 1 列，資料從第 2 列起）
}
```

## 操作步驟

1. 登入後進入「教師管理」頁籤（僅教務主任看得到此頁籤）。
2. 點「📥 批次匯入 CSV」，選擇準備好的 CSV 檔案。
3. 系統會先解析檔案並試算結果，跳出「CSV 匯入預覽」對話框，列出：
   - 新增 / 更新 / 略過 / 錯誤 各幾筆
   - 每一筆錯誤的「第幾列、姓名、原因」，方便回去修正 CSV
4. 確認數字無誤後按「確認匯入」才會真正寫入 Firestore；按「取消」或點對話框外側背景則不會寫入任何資料。
5. 匯入完成後，教師列表會自動重新整理，並跳出通知顯示本次結果摘要。
6. 若某些列有錯誤，修正 CSV 後可直接重新上傳整份檔案再匯入一次——已成功的列會因為冪等性規則
   被歸類為「略過」，不會重複建立或造成資料錯亂。
