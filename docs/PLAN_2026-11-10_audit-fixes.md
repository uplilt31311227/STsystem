## 共同規則

- 每階段流程：實作（sonnet）→ 驗收（opus，fresh agent，實跑測試）→ 通過才 commit → 下一階段。
- 階段依序執行，不平行（`app.js`、`v2-app.js`、`firestore.rules` 被多個階段共用）。
- 每個修復都要有對應測試：邏輯類加 node 測試並掛進 `npm test`；rules 類加 emulator 測試；能重現的 bug 先寫出會失敗的測試再修。
- 每階段結束必跑：`npm test`、`npm run check`；動到 rules 或 Firestore 流程的階段另跑 emulator 測試（`demo-stsystem`，不得指向正式專案）。
- 不改既有測試的期望值來讓測試通過；若既有期望本身是錯的，在回報中說明。
- 階段內不部署、不動正式庫。部署集中在 P10。

## P0　準備

- 跑 `node scripts/firestore-backup.js backup`（對正式庫唯讀匯出）。115-1 課表沒有匯入快照，備份是唯一復原手段。
- 啟動 emulator，跑完整測試（`npm test`、`npm run check`、`test:scenarios`、各 `test:rules-*`、`v2-rules-matrix`）記錄基線，之後各階段以此對照。

## P1　GitHub Pages 只發布網站檔案

- 問題：部署 workflow 上傳整個 repo，`docs/`、`scripts/`、`test/`、rules、交接紀錄都公開。
- 修法：workflow 先把 `index.html` 與 `src/` 複製到發布資料夾，只上傳該資料夾。
- 驗收：本機模擬複製步驟，確認發布資料夾只有這兩項，且 `index.html` 引用的本地資源全部存在。

## P2　日期時區

- 問題：以 `toISOString()` 取日期，台灣時間 00:00–07:59 會得到前一天；影響預設日期、檔名、部分日期運算。
- 修法：新增單一的本地日期格式化工具，替換所有「取日期」用途（`app.js:758`、`:3211`、`:3357`、`:4929`、`:5669`；`dataManager.js:615`；`v2-app.js:1439`、`:2283`；其餘逐一判斷）。時間戳用途（`createdAt` 等）維持 ISO 不動。同時處理 `new Date('YYYY-MM-DD')` 被當 UTC 解析的地方。
- 驗收：新增測試，在 `TZ=Asia/Taipei` 下模擬 00:30 與 07:59，預設日期與日期加減結果正確。

## P3　身分與授權（rules 為主）

| 項目 | 修法 |
|---|---|
| 未驗證 email 可綁定教師身分 | rules 的身分綁定、白名單主任判定、emailIndex 讀取都要求 `email_verified == true`；前端對未驗證的密碼帳號顯示「寄送驗證信／重新整理」畫面 |
| mapping 永不撤銷 | 成員與角色判定改為同時要求教師檔存在且 email 與登入者相符；刪除教師或變更 email 時一併刪除 mapping；提供清理既有孤兒 mapping 的腳本（預設 dry-run） |
| 同意人可替別人同意 | 同意欄位的更新只允許增刪自己的 uid |
| 可替別人補建私有明細 | 私有明細的建立限申請人本人或 approver |
| 稽核日誌可偽造 | 日誌的 actor 欄位必須等於登入者；時間戳必須是伺服器時間；欄位白名單與長度上限 |
| 申請與紀錄沒有欄位白名單 | 申請、自我調課紀錄加欄位白名單、型別與長度限制；禁止寫入 `id`、`reqId`、`recordId` 等保留欄位；`createdAt` 必須是伺服器時間；`affectedTeacherIds` 必須與紀錄內的教師一致 |
| V1 `users/{uid}/**` 無限寫入 | 限制為已是某校成員才可寫，並限制路徑與文件大小 |
| 規則測試漏測 | 補上審計列出的 17 條漏測路徑 |

- 相容性風險：既有以密碼登入且未驗證 email 的教師會被擋。前端驗證流程必須同批上線。
- 驗收：emulator 規則測試全數通過；每個項目各有「攻擊被拒」與「正常流程仍可行」兩類案例；既有 `v2-rules-matrix`、`v2-approval-flows`、`test:scenarios` 不退步。

## P4　前端輸出跳脫與相依套件

- `v2-app.js` 所有以模板字串組 HTML 的地方全面跳脫（操作日誌表、紀錄表、待辦卡片、頁首姓名、平台管理面板等，依審計的 sink 總表逐一處理）；屬性值一併跳脫。
- `schoolDataService.js` 所有 `{ id: d.id, ...d.data() }` 改為 `{ ...d.data(), id: d.id }`；`pendingRequestService` 核准複製時剔除保留欄位。
- `app.js` 課表編輯格線跳脫。
- 科目→領域對應表改用無原型物件或 `Map`。
- `index.html` 加 CSP（meta）；CDN 腳本鎖版本並加 SRI；SheetJS 升級到已修補版本。
- 登出時清除 Firestore 離線快取與本機課表鏡像。
- 驗收：新增測試以帶 HTML 特殊字元的資料餵各渲染函式，輸出不得含未跳脫的標籤或跳出屬性；CSP 上線後以 Playwright 在 emulator 開站，console 無 CSP 違規、匯入課表與產生 PDF 正常。

## P5　資料遺失防護

- 「匯出完整備份」在 V2 下改為匯出雲端資料（課表、所有學期紀錄、待審申請、教師名冊）；「匯入還原」在 V2 下改為明確寫回雲端並二次確認，或在做不到完整還原時隱藏並改掉文案。
- 「清除所有資料」對話框文案與實際備份能力一致。
- 「開新學期」：目標學期已存在時不覆寫其課表，改為單純切換；修正確認框的復原建議文字。
- 課表匯入：加預覽（節數、班級數、教師數、與現有課表的差異）與確認；匯入前自動建立快照。
- 「先開學期再匯入」防呆：匯入時顯示目標學期並要求確認。
- 全校課表寫入加版本檢查，避免兩位組長互相覆蓋。
- 驗收：emulator 情境測試——對已存在學期開新學期後課表不變；匯出檔含全部學期紀錄；匯入可由快照還原。

## P6　衝堂與申請流程

- 時段佔用判斷涵蓋調課的時段 B：送出檢查另查以調課日期為條件的紀錄；核准重驗納入班級時段；V1 路徑與推薦引擎同步修正。
- 建立「當日有效課表」：套用已成立的調課後再做請假、推薦與衝突判斷。
- 批次調課：核准、駁回、撤回以批次為單位，或在單筆核准時重驗批次依賴；組長自送批次改為全有或全無。
- 撤回前檢查狀態，已核准的不可撤回。
- 組長代發與核准的衝突重驗放進交易；所有送出鈕防連點並顯示處理中。
- 重新匯入課表或刪除教師後，標示受影響的在途申請與紀錄。
- 同名教師的 teacherId 解析不再取第一筆，改為要求明確選擇。
- 驗收：審計的重現腳本改寫為測試並全數轉為通過；emulator 併發案例（同節雙送、雙核准、連點）只成立一筆。

## P7　月結算正確性

- 結算依月份所屬學期取課表與名冊；跨學期月份分段計算。
- 教師集合 = 名冊 ∪ 紀錄中出現的人；姓名統一正規化（trim、全形空白）；同名以 teacherId 區分。
- 每週節數去重（完全重複列、合班、隔週課）。
- 核准時讀私有明細失敗不可吞掉，改為中止並提示。
- 假別補齊（婚假、產假、陪產假、公傷假、流產假等）並定義各自是否扣時數。
- 超鐘點門檻改為可逐人設定（預設沿用 20 節）。
- 行事曆關鍵字判讀修正（「不放假」、部分年級停課）。
- 「九年級已畢業」改存雲端、依學期重置並可設生效日期。
- 結算查詢快取失效條件修正。
- 驗收：以固定資料集比對結算數字（含跨學期、離職代課者、同名、合班案例），新增測試掛進 `npm test`。

## P8　使用者體驗

- 「待我同意」卡片顯示時段 B；「待我審核」卡片顯示代課教師、假別、事由與相關調課。
- 「其他教師需同意」對話框加取消鈕、修正標題、名單可搜尋。
- 新教師首次登入：說明學校代碼是什麼、向誰取得；公告同步更新。
- 登入遮罩小螢幕可捲動。
- 對話框統一：`role="dialog"`、Esc 關閉、焦點管理；含輸入的對話框點背景不關閉。
- 核心申請流程可用鍵盤與螢幕報讀操作（radio、開關、課程格、推薦項目、上傳區）。
- 色彩對比未達標的 8 組調整到 AA；焦點環可見。
- CDN 腳本加 `defer`（確認載入順序相依）。
- 驗收：既有 `ui-rwd-check` 與 e2e 不退步；新增鍵盤走查腳本；對比值重算全部達標。

## P9　其餘 Medium／Low

- 依五份審計報告的 Medium 與 Low 清單逐項處理；每項標記「已修／不修（理由）」，結果記入 `docs/ISSUES_LOG.md`。
- 管理腳本：預設 dry-run、寫入需明確旗標並顯示目標專案；規則部署腳本加確認與 git 狀態檢查。
- 推薦引擎的兼課教師到校時段、每日／每週上限屬功能擴充，在此階段評估後決定實作或列入 backlog。

   - 合併進 `master` 並 push（觸發 Pages）。
